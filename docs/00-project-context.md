## 1. 一句话

在正式申报前，对一票**进口一般贸易**货物的随附单证做自动审核——查四单一致性、查申报要素、给归类建议、提示监管证件，输出「可申报 / 可补正 / 需复核 / 不可申报」，高风险单转人工。

## 2. 为什么做（真实动机）

用户要投 **宁波国际物流发展股份有限公司 · AI技术发展部 · 智能体开发工程师**，需要一个能讲 40 分钟的 0→1 项目。用户**不熟悉物流/关务业务**，业务判断由助手（本项目中的“业务资深人员”角色）负责；用户负责拍板方向。

目标岗位 JD 的硬要求（原文摘要）：
- 设计单/多智能体与自动化工作流，建**轻量 Harness 层**：Agent Loop、模型路由、工具/MCP、上下文/记忆、状态、权限、护栏、人工审批、重试与降级
- 建 RAG 知识系统：数据治理、切分、Embedding、**混合检索、重排、引用溯源、增量更新**
- **评测驱动**：数据集、离线/在线评测、回归、红队；LLM-as-a-Judge
- 生产级：容器化、CI/CD、Tracing、指标告警、成本/延迟/安全
- **FDE 方式深入客户现场**，按采用率、任务成功率、业务收益衡量

## 3. 目标公司业务研究（已核实）

- 宁波国际物流发展股份有限公司，2003 年成立，**国有控股**（宁波市政府主导，宁波交通投资集团、宁波舟山港集团、宁波信息港共同出资），国家高新技术企业。
- 不是货代、不是快递公司，而是**口岸 + 关务 + 跨境的政务/产业互联网平台运营商**，核心资产是平台与数据通道。
- 六大业务：智慧口岸、智慧关务、跨境电商、智慧物流、物联网、智慧交通。
- 运营平台：宁波电子口岸、中国（宁波）国际贸易单一窗口、四方物流市场、跨境购、进口商品溯源中心。
- **关键事实：智慧关务产品线里已经有「AI 智能单证识别」**。所以我们做的是识别之后那一步（判断层），不重复造识别。

## 4. 范围

**做**
- 进口一般贸易（不做加工贸易、不做跨境电商 9610/1210 清单）
- 输入是**结构化 JSON**（合同、发票、装箱单、提单、报关单草单）
- 四层校验 + 四分类结论 + 人工审批门

**不做（明确写出来，防范围蔓延）**
- OCR / PDF / 图片解析（定位为“已有能力”，我们只消费解析结果）
- 自动申报（不碰单一窗口/海关系统，仅输出审核意见）
- 自动改判 HS 编码（只给 6 位建议）
- 真实客户数据

## 6. 架构总览

```
单证 JSON ──► 解析/规整 ──► 规则引擎(L1/L2/L4) ──┐
                              │                    ├──► 汇总结论 ──► 审批门 ──► Web 审核台
                              └─► RAG 规则检索 ────┤        │
                                   (L3 要素/归类)  │        └─► 转人工(REVIEW)
                                                   └─► LLM(仅 L3-25/26/29)
```

**Harness 七件套**：Loop（步数预算 8）｜Router（规则优先，LLM 兜底）｜工具注册（JSON Schema + 超时 + 重试）｜记忆（单票工作记忆 + 会话记忆）｜状态（审核单状态机持久化，审批中断可续跑）｜护栏（只读输入、结论带引用、输出 schema 校验）｜Tracing（JSONL，每步的输入/耗时/token/成本）。

**关键取舍（面试要讲的三条）**
1. 字段比对**不让 LLM 做**——确定性规则更准、更便宜、可解释。
2. 审批门放在**工具层**而非 UI 层——CLI 和 Web 复用同一套。
3. 结论**必须带引用**——这是压幻觉的硬约束，也让报关员敢用。

## 8. 规则库设计原则

- **L1/L2/L4 全部确定性规则**，不花 token；只有 L3 的品名-编码冲突、规格矛盾、归类建议用 LLM。
- **漏报比误报致命**：结论分级宁可疑不可放；但为避免业务方弃用，用「PASS 用例防误报」压住误报率。
- 每条规则必须有：编号、判定逻辑、违反时结论、来源（填制规范 / 税则 / 内审 SOP）。
- 44 条已定稿，见 `01-rule-library.md`。

## 9. 评测设计要点

- 60 条，**先写评测再写代码**；数据全合成，缺陷是注入的。
- 分布：PASS 18（含 4 条容差边界）/ 单证不一致 16 / 要素与归类 10 / 监管证件 8 / 多缺陷叠加 8；另 15 条脏数据分散其中。
- 指标：四分类准确率、**差异字段召回率**（最重要）、误报率、引用命中率、人工复核率、平均步数、P95 延迟、单票成本。
- 期望值来源有限（无报关员标注），必须单列《期望值来源与局限》。

## 11. 验收记录（2026-10-26，业务视角）

对 v1.0 的 40 条规则与 60 条评测分布做了业务复核，**有条件通过**，已修正为 v1.1：

| 问题 | 原写法 | 修正 |
|---|---|---|
| **运保费规则写反**（致命） | “FOB 不得申报运费保费” | 进口 FOB/CFR 时买方支付的运保费**应计入完税价格**；CIF 不得重复计入 |
| **申报要素维度错** | 按 HS 前 6 位取要素集 | 规范申报要素按**10 位**商品编号确定，6 位不够 |
| **缺完税价格构成**（致命缺口） | 无 | 新增 L4-41：运费/保费/佣金/特许权使用费是否计入 |
| **缺申报期限** | 无 | 新增 L4-42：进境 14 日内申报，逾期滞报金 |
| **监管证件结论过重** | 缺失即 REJECT | 改为 REVIEW（可补办）；REJECT 只留给禁限类 |
| 日期顺序过严 | 发票日 ≤ 提单日 硬性 | 只保留“提单日 ≤ 申报日”硬性，发票日仅告警 |
| 毛净重写法歧义 | “毛重 ≤ 净重” | 改为“毛重 < 净重”才违反 |
| 金额勾稽未扣折扣 | 单价×数量 = 总价 | 需先扣折扣/佣金 |
| 超 50 项结论 | FIX | 改为 REVIEW（需拆单，非补正） |
| 贸易方式不匹配 | REJECT | 改为 FIX（可改单） |
| 评测缺多缺陷叠加 | 无 | 新增 8 条（真实单据常同时 2–4 个问题） |
| 评测脏数据不成立 | “扫描噪声” | 结构化输入下改为字段错位/空值/单位混用 |

### W2 实现期发现（2026-10-26）

1. **总额容差必须收紧到 0.1%**：v1.1 写「金额 ±1%」，但报关单总价是精确值，1% 会把 120 USD 的差额判为通过。
   已改：`L2-13` 总额容差 0.1%，`L1-07` 行级勾稽仍 1%（单价四舍五入会漂）。
2. **境内目的地不是国别**：`L1-10` 原先拿 `destination` 去匹配国别表，导致所有正常单据误报。已改为只校验启运国。
3. 这两条都是**评测跑出来的**，不是审出来的——说明先写评测再写代码是对的。

## 13. 风险
