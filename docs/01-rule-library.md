# 01 · 审核规则库 v1.6（46 条）

> 适用：进口一般贸易 ｜ 输入：结构化单证 JSON ｜ 输出结论：`PASS` / `FIX` / `REVIEW` / `REJECT`

## 结论定义

| 结论 | 含义 | 后续动作 |
|---|---|---|
| `PASS` | 未发现问题，可直接申报 | 报关员确认 |
| `FIX` | 有明确、可自动给出修正建议的问题 | 报关员一键采纳或手动改 |
| `REVIEW` | 需要人判断（规则冲突、专业归类、证件补办） | 转主管复核 |
| `REJECT` | 依规不得申报（禁限、缺前置资质） | 退回货主 |

## 变更记录（v1.0 → v1.1）

1. **L2-19 运保费规则重写**：原写“FOB 不得申报运费保费”，与进口完税价格规则相反。FOB/CFR 进口时，买方实际支付的运至境内输入地点起卸前的运输费、保险费**应计入完税价格**；CIF 时不得重复计入。
2. **L3-23 要素维度改为 10 位**：规范申报要素按 10 位商品编号（本国子目）规定，前 6 位不足。
3. **新增 L4-41 完税价格构成**：这是海关审价的核心，原版完全缺失。
4. **新增 L4-42 申报期限**：进境 14 日内申报，逾期滞报金。
5. **L4-33 结论降级**：监管证件缺失从 `REJECT` 改为 `REVIEW`（可补办）；`REJECT` 只留给禁限类（L4-36）。
6. **L1-02 放宽**：仅“提单日 ≤ 申报日”为硬约束，发票日早于提单日只告警。
7. **L1-08 表述修正**：违反条件是“毛重 < 净重”。
8. **L1-07 补折扣**：需先扣除折扣、佣金后再勾稽。
9. **L1-05 结论改为 REVIEW**：超 50 项需拆单，不是补正。
10. **L4-35 结论改为 FIX**：贸易方式/征免性质不匹配可以改单。
11. **新增 L4-43 木质包装 IPPC、L4-44 许可证有效期**。

## 变更记录（v1.1 → v1.2，W2 实现期）

12. **L2-13 总额容差收紧到 0.1%**：总额是精确值，1% 会放过 120 USD 级别的差额；行级勾稽 L1-07 仍用 1%（单价四舍五入）。
13. **L1-10 不再校验 `destination`**：境内目的地是国内地区编码，不是国别，原写法导致全部单据误报。

## 变更记录（v1.2 → v1.3，W4 实现期）

14. **L3-23 与 L3-27/28/31 分工**：L3-23 只查非专项文本要素；材质、用途、工艺各由专项规则负责，
    避免同一缺陷报两次、也便于分别统计召回。
15. **L3-27 的“无效”判定改为只认占位词**（未知/其他/待定/无）：原“长度 < 2 即无效”在中文里不成立，
    “棉”“钢”都是合法材质。
16. **L3-29 只发低危提示，永不改变结论**：遵守 D3（只给建议、不改判 HS）。
17. **L3-25 用“关键词 → 章节 → 具体度”表**，具体度 ≥ 4 才判冲突；否则“塑料”这类泛词会把
    95 章的玩具误判到 39 章。

## 变更记录（v1.3 → v1.4，W6 测试期）

18. **L2-11 名称匹配收紧**：jaccard 从 `>= 0.5` 改为 `> 0.5`，并对英文复数做归一
    （`PARTS → PART`、`TOYS → TOY`）。修复“塑料制具配件 vs 塑料制玩具配件”只差一个字却漏报的问题；
    60 条回归集准确率/召回/误报均未退化。
19. **L2-18 扩展交易双方**：除提单收货人/通知人 vs 报关单收货人外，新增
    “合同买方 vs 发票买方”“发票卖方 vs 提单发货人”。公司名比对忽略 `LTD/LIMITED/PTE` 等法律形式词，
    但仍能识别 `GLOBAL TOYS` vs `GLOBAL TOS` 这种一字之差。

## 变更记录（v1.4 → v1.5，W6.3 单证复查驱动）

20. **L1-02 不再静默跳过脏日期**：新增"有值但不可解析"判定，报 `日期格式非法`（mid）。
    此前 `date.fromisoformat` 失败即返回 None，时序校验被无声跳过。
21. **L1-03 币制表扩到 ISO 4217 全量**（18 → 160+），并把合法性校验从报关单扩到合同/发票。
    先扩表再校验：否则 `SDG`（苏丹镑）这类合法代码会被小表误判成非法。
22. **L1-04 补第二法定单位与单位合法性**：报关单缺 `legal_unit2` 报 high；报关单/发票的成交单位、
    第二法定单位不在单位表内（如 `个f`、`千克d`）报 mid。**"单位与商品编号不匹配"仍未实现**，
    需先引入税则法定单位表，留到下个版本。
23. **L1-10 口径补齐**：HS 格式从"只查报关单"扩到发票/箱单/提单/报关单四单；新增单号字符集校验
    （非 ASCII / 含空白）。数字位被改写的单号笔误（如 `PL-2026-d0901`）无法通用识别，仍属不可判。
24. **L2-19 先判成交方式合法性**：不在 Incoterms 2020 表内的值（`OB`/`FOpB`）报 mid，
    不再从三个分支一起滑过；并新增合同/发票/报关单成交方式一致校验。
25. **L2-21 补发票侧**：发票合同号与合同不一致报 mid（原实现只比报关单，
    规则文本"合同号出现在发票上"没落地）。
26. **L4-35 代码表查不到要报**：贸易方式不在代码表内报 mid，避免脏文本让整条规则静默通过。
27. **L4-42 期限无法核定时要报**：到港日有值但解析失败报 `申报期限无法核定`（mid），不再直接 PASS。

28. **新增 L2-23 合同金额勾稽**：`contract.total_amount` vs `invoice.total_amount`，容差 **1%**。
    合同允许分批装运/溢短装，0.1% 会把正常业务判成错误；1% 与 L1-07 行级口径一致。
29. **L2-18 补卖方链**：合同卖方 vs 发票卖方（原来 `seller` 取 `invoice.seller or contract.seller`，
    发票有值时合同卖方永不参与比对）。
30. **新增 L2-24 要素跨单一致**：发票 vs 报关单只比 `brand_type / material / use` 三键，
    且**双方都有值时才比**——缺失留给 L3-23/24，避免同一缺陷报两次。
31. **L2-11 扩英文品名**：中文名一致而英文名不一致时出 low 提示，**不改变结论**（避免中英混写误判）。
32. **L2-12/15/16 补齐四单口径**：数量加提单；毛重加报关单；净重加提单（提单无净重时自动跳过）。
    L1-07 补报关单行级勾稽，散装货按 3% 溢短装放宽（否则 IMP-0008 会误报）。

## 实现约定

- 每条规则实现为 `Rule` 对象：`id / layer / check(ctx) -> list[Issue] / conclusion / source`。
- `Issue` 字段：`rule_id / field_path / severity(high|mid|low) / message / evidence / suggestion`。
- 规则之间可以冲突（例如 L2-12 与 L3-30 对数量口径不同），冲突时取**更严重**的结论，并在报告里注明冲突。
- 规则库以 `data/rules/rules.yaml` 为唯一事实源，文档由脚本从 yaml 生成，避免文档与代码漂移。
